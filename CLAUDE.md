# catbird-mls

## Overview

`catbird-mls` is the core MLS (Messaging Layer Security) SDK for all Catbird clients. It implements OpenMLS group cryptography (pinned at `=0.9.0-rc.3`, rev `e7c2437e845eb767d2cdd22eece2b3c5d484e4e7`; do not change the pin), the `CatbirdMlsClient` SDK with its Labyrinth history archive, a platform-agnostic orchestrator (sync, recovery, messaging policy), and UniFFI bindings, so Swift and Kotlin call one Rust library. It also contains voice encoding (Opus/OGG) and blob crypto (AES-256-GCM), which makes it a monolith that should eventually be split. The spec that governs all behavior is `docs/MLS_CLIENT_PROTOCOL.md` in the Catbird+Petrel workspace root, not in this repo.

## Architecture

### The Four Platform-Agnostic Traits

```
MLSOrchestrator<S, A, C, M>
  S: MLSStorageBackend     — persistence (conversations, messages, groups)
  A: MLSAPIClient          — HTTP to mls-ds and nest
  C: CredentialStore       — signing key, DID, device UUID (keychain/keystore)
  M: MlsCryptoContext      — synchronous OpenMLS operations
```

On iOS/Android: each trait is a UniFFI callback interface (Swift/Kotlin provides the impl).
On WASM/CLI: Rust implementations used directly.

**Send order (seed 2323/3966 contract).** Every application send signs `(generation, epoch, sendCounter)`. Every send path (`CatbirdMlsClient`, `MLSOrchestrator`, web `WasmMlsClient`) reserves the per-conversation `sendCounter`, advances the OpenMLS sender ratchet and writes the immutable pre-HTTP send journal in `pending_ops`, all in one storage transaction. A timeout may still publish that ciphertext. On the first `StaleSend` the refused journal is deleted and the message is re-encrypted once at a fresh counter. On any further `StaleSend`, or a failed reservation, the refused journal is deleted immediately; refused bytes are never resubmitted. `GroupConfig` uses a sender-ratchet window of 10 out of order / 2,000 forward on every live create/join path.

**Creation order (seed 297 contract).** Before its first `createConversation` HTTP call, group creation durably journals one staged epoch-zero `KvWriteBatch`, the sequencer DID, and the exact first signed attempt. Attempts are append-only: the resolver replays every byte-identical request that could have committed and adopts any verified answer or own sequenced creation in one transaction with journal deletion. Client open is storage-only; `create_group`, `sync`, and explicit `retry_pending_group_creation` drive resolution, with only the explicit retry bypassing the bounded exponential/`Retry-After` delay (capped at 300 seconds). The current endpoint is resolved for the journaled sequencer DID rather than persisted. A refusal, timeout, malformed answer, unavailable state read, or unverifiable entry proof retains the journal and is visible through `pending_group_creation_status`. Authenticated server time must put every attempt beyond the 300-second freshness window plus 60-second skew before verified absence/foreign ownership can permit deletion, permanent rejection, cancellation, or a new signed attempt around the same staged group. `cancel_pending_group_creation` also shares the in-flight guard; an own existing creation is adopted, and any possibly executable or unproved attempt returns `GroupCreationCancellationUnproven`.


**Cursor rule.** `sync()` advances `last_seq` or acknowledges an entry only after verifying the entry's I13 receipt under the exact key ID it names, the original-sender attestation, and active-roster membership. This applies to every entry kind: an undecryptable current-epoch tombstone, `payloadPruned`, `already_have`, an own echo and a control entry. A missing local group is an error. `sync()` recovers an own echo's plaintext and archive queue from the journal only after matching the exact ciphertext and verifying the receipt; it never decrypts or blindly skips an own-message echo. Imported history does not advance the live entry cursor.

Joined clients discover fulfillable leaf-recovery requests through
`getConversationState.pendingLeafRecoveryRequests`; `getLeafRecoveryInbox` belongs
to the requesting device. Classify stale transitions by the exact XRPC
`StaleCoordinates` error, not HTTP 409: the delivery service returns HTTP 400.

A generic `#commitTransitionBody` Commit must carry zero participant changes, so
`remove_group_member` is two steps: a Commit removing every target leaf (carrying
`removed_participant_did` in `PendingCommitTransition` and recording a
`participant_removal` pending op once that own Commit is accepted or recovered), then a
`#policyTransitionBody` `removeParticipant` at the server's coordinate once the target
has zero leaves. `sync()` authenticates `policyTransitionEntry` wrapper signatures and
resumes the policy step after a lost response or a journal-recovered Commit.
An accepted local Commit with a preceding entry-sequence gap stays journaled without
advancing the durable MLS group or evicting its prior roster. Ordered entry sync first
authenticates the preceding applications under strict `I4`, then recovers the own Commit
and completes any participant-removal policy. The same rule applies to leaf recovery.

Whether a refused request may be replayed with identical bytes is decided in one place,
`canonical_transport::is_transient_wire_failure`: `CapacityUnavailable` (sent as HTTP 400
when a coordinator or recipient home is unreachable or a relay fails; nothing durable was
recorded), 408, 425, 429 and 500/502/503/504 are transient; any other status, including a
semantic 4xx and 501, is terminal for those bytes. `retry_after_secs` accepts only
delta-seconds `Retry-After`, capped at the 300-second preparation lease; an HTTP-date is
ignored, so deferrals run on the injected clock. Pending commits, participant removals,
request acceptances and C33 creations discard their journals only on a semantic 4xx; every
5xx keeps them. The orchestrator's `resume_direct_request` maps a non-200 prepare or publish
through `map_wire_error`. A transient refusal stays `OutcomeUnknown`. `GatewayResponse`
carries no headers, so `CapacityUnavailable` uses the delivery service's 5-second contract:
the instant is persisted on the intent (`retry_not_before_ms`, wall-clock unix ms), a resume
before it sends nothing, and reconciliation skips the draft until then, across restarts. A
semantic refusal returns `TerminalNotPublished` with its code; any 200 or semantic answer
clears the deferral, and otherwise the intent is unchanged. Background reconciliation parks
such a draft for the process lifetime instead of resending it on a timer.

`accept_direct_request` journals its signed `acceptConversation` request as a
`direct_request_acceptance` pending op and replays those exact bytes until consent is
recorded (with the journal removal) or a terminal refusal: the delivery service keeps
the first acceptance even when relaying it to a remote coordinator fails, so a freshly
signed retry is an `IdempotencyConflict`. Accepting an already accepted request is a
no-op, and a synced acceptance entry also clears the journal.

An untitled 1:1 `create_group` (a C33 request) journals its attempt as one
`direct_request_creation` pending op per peer DID, because the server fences one live
preparation per pair while the app names a new conversation on every tap. The signed
prepare is journaled before it is sent. After a successful prepare, the MLS bootstrap
(an unapplied `KvWriteBatch`) and the signed publication are journaled before publishing.
Each retry, including after a restart, resumes that attempt and returns its conversation,
request and introduction text, not the caller's. It replays the exact bytes and never
rebuilds MLS or prepares again, which would reserve another recipient key package. A
transient refusal records its `Retry-After` on `hooks.now_ms()`; a retry before then
returns the same error without any request. A terminal refusal or a signed
non-publication receipt (rejected, expired, existing direct) discards the journal, but only
after the receipt verifies like a publication outcome: the coordinator's receipt signature,
the journaled request, its prepare (or publication) digests and the actor. Anything else
fails closed and keeps the journal. The write that commits the published bootstrap also
deletes it. A lost response keeps the journal.

C33 openings use an encrypted version-2 envelope containing `frameNonce` and the
canonical `MLSMessagePayload`. The signed publication and MLS AAD bind the same blinded
`archiveCommitment`; the publication outcome and delivered entry must carry the I13
sequencer receipt. The publication-receipt key and the I13 receipt key are independent
trust checks; each is resolved from the key ID in its own signed evidence (an exact retained
`#mls-receipt-N` method), never a hardcoded `#mls-receipt-1`. Incomplete legacy openings fail closed instead of becoming
unsigned archive frames.

An imported opening is staged with its frame, nonce and I13 receipt (`c33_pending_opening:{cid}`).
It is queued for the archive only after acceptance; a decline or close discards it.

A **pruned** opening (`payloadPruned: true`, no `signedRequest`) keeps only its receipts.
`sync()` verifies the coordinator-signed `publicationReceipt` and its I13 `sequencerReceipt`
against the row: the conversation, `firstMessageId` equal to `entryId`, `recordedAt` equal to
`receivedAt`, the seq and the commitment. It then records the request as `openingUnavailable`
(`C33_OPENING_UNAVAILABLE`). That state is terminal: there is no message row, Welcome import,
preview or acceptance (`accept_direct_request` returns `InvalidState("OpeningUnavailable")`).
The conversation's history is reachable only through its Space.

Labyrinth adapters map exact `NotEntitled` and `AccessOutsideMembershipInterval`
protocol errors to `Forbidden`. Only a real `Forbidden` or a locally authenticated
kick/leave permits owner-mailbox fallback; a missing active conversation/Space fails
closed. Committed owner frames require both a trusted sequencer signature and the
blinded `archiveCommitment`, never commitment-only attribution.
The full receipt is bound into owner AEAD. A fresh removed device may bootstrap its
receipt-key lookup from that authenticated issuer, never from an untrusted public
receipt; an existing sequencer pin cannot be overridden.

A joined group's `sequencer_did` and Space authority are pinned at initial bootstrap.
Unsigned inventory may fill an empty pin but cannot replace one or rewrite a reserved
application send; changing authority requires a verified transfer. NSE commits reconcile
conversation coordinates from authenticated MLS AAD and the merged group before an app
can reserve a sender ratchet step.

### Native archive contract (Labyrinth over Spaces)

**Status (2026-11-07).** This section describes the unsealed Task 4 contract on top of the bookmark.
- The bookmark `clean-slate-2026-10-31` is R0 (`79a40b5f`). The latest reviewed cut is `bb43b958`, built against `labyrinth@276c0972` (path dependency `../labyrinth`).
- The independent R3 review of that cut failed. Fix Round 4 is changing this contract as described below; nothing is sealed.

Protocol detail is in `../labyrinth/docs/SPACE_CONVERSATIONS.md` and `../labyrinth/docs/MLSDS_BACKEND.md`.

**Identity.** Production `open` and `open_with_hooks` reject any device ID that is not UUIDv4, and every archive call re-checks it. The Space-only harness (`src/client/offline_archive.rs`) uses a static per-conversation sender MEK instead of real MEK distribution. It compiles only under `test`, `test-utils` or `sim`, and only `open_offline_archive_for_test` or `open_offline_archive_with_hooks_for_test` selects it. A device ID's shape never selects weaker archive behavior. Run its integration targets with `--features sim`.

**Session.** `native_archive_deps` builds a `LabyrinthSession` whose directory is always `CompositeDirectory::new(PdsDirectory, DsDirectoryStore)`. A peer head must agree between the peer's public `mailboxKeys` and mls-ds; otherwise the result is `DirectoryIncomplete` or `DirectoryFork`. Each new epoch is published to the account PDS (`mailboxKeys/<12-digit epoch>` create-only, then `self` under `swapRecord`) and to mls-ds (`publishEpochHead`). Opening a session backfills a missing or stale PDS copy. Session state and Space pins live in `labyrinth_state` (`native.session`, `native.placements`).

**Space reads** pass through `native_archive_space.rs` before any byte reaches Labyrinth:
- a fresh P-256 credential key per request, and a delegation token from the account PDS;
- a credential exchange: `getSpaceCredential` for the mailbox, `blue.catbird.chat.relaySpaceCredential` for a conversation;
- an HTTP-signature proof of possession, a fresh KEM share, and exactly one `Atproto-Space-Mac`;
- URI, CID, LtHash and STAR checks.

`getBlob` sends `space`, `repo` and `cid`, and the body must hash to that CID. A 401 or 403 is the Space's `Forbidden`. Any other failure fails closed.

**What is queued.** `QueuedLabyrinthArchivePayload` carries:
- the canonical `MLSMessagePayload` frame and its `frameNonce`;
- the verified I13 receipt;
- `expected_member_dids`, the authenticated MLS roster at send or receive time, which a flush never replaces (`I5`).

Rows are created as follows:
- An own send is enqueued, with its message row, only after the accepted response's I13 receipt verifies (`finish_application_send`).
- Every verified message from another account is enqueued as a witness copy under the receive-time roster. NSE-decrypted messages wait until `sync()` verifies their receipt.
- The same evidence is kept under `native.message:{cid}:{id}` for rescue.

**Flush.** The platform calls `flush_labyrinth_queue`; nothing flushes on the send path. It visits queued conversations only, in 100-row pages grouped by group, epoch and roster. For each conversation:
- `getConversationState` succeeds and the local MLS roster holds this account: sender batches;
- the state read is `Forbidden`, or the local roster lacks this account: owner batches;
- a sender write returns `Forbidden`: that chunk goes to owner batches;
- anything else fails that conversation and keeps its rows. That includes `ConversationNotFound` while the local roster still holds this account, `DirectoryIncomplete` and Space verification failures.

Rows are dequeued only after their page is written, so a retry can republish identical copies, which readers merge. The first error is returned after every conversation has been tried; `ContextClosed` aborts at once. Roster members that fail a trust check are excluded with a warning. A deleted account is left out of the roster only on a verified `accountDeletedEntry`, never on a 404.

**Receiptless rows are not a production path.** A queued row without I13 evidence fails its conversation's native flush (`ReceiptCommitmentMismatch`) and stays queued, which also stalls the rows behind it. Production `create_group`, `send_message`, `add_group_members` and `remove_group_member` therefore reject a conversation, message or device ID that is not UUIDv4 with `InvalidInput` before any MLS, database or archive effect. `add_group_members` also rejects a call that names no other account with `InvalidInput`. Both membership calls fail with `GroupNotFound` for a conversation not held locally; neither returns an unchanged row or a silent `Ok`. The local-only `create_group_local_offline`, `send_message_local_offline` (the only producer of receiptless rows) and `remove_group_member_local_offline` compile only under `test`, `test-utils` or `sim`. They are taken only on a client opened with `open_offline_archive_for_test`, whose flush is `offline_flush_labyrinth_queue`, never the native flush. An ID's shape never selects them.

**Owner fallback.** OwnerBatch is used only for `Forbidden` from the authenticated Space authority, or an authenticated local kick or leave. `rescue_conversation_on_kick` runs from `sync()` after a verified Commit removed this device. It seals each local message from its retained evidence, plus the queued rows, with `archive_owner_committed`. A message whose own evidence fails validation is skipped and recorded in `native.rescue-report:{cid}` (`skippedEvidenceIds`); the rest are rescued. A transport, directory or Space failure fails the rescue and keeps the rows for retry. A missing active Space or conversation fails closed.

**Restore.** `restore_conversation_from_owner_mailbox` restores an active member from the conversation Space (sender and witness copies). It uses owner copies only when the authenticated Space denies access or the verified local roster lacks this account. A fresh device that gets HTTP 400 `NotEntitled` or `ConversationNotFound` from its home DS treats that answer only as a lead. It must first open authenticated owner evidence, recover its receipt-bound Space pin, and confirm denial through that Space. An unsigned home-DS 4xx is never denial evidence. Generic 400, authentication and directory failures fail closed.
- Any undecryptable or unverified frame fails the restore.
- Rejected witness copies are logged and ignored.
- When copies of one message ID disagree, the copy equal to the local message wins; with no local match, that ID is skipped.
- Rows take the receipt's group, epoch and seq, and never advance the live cursor.

**Account deletion.** `sync()` verifies each `accountDeletedEntry`: low-S ES256 under the exact retained `{sequencerDid}#mls-receipt-N` method over `catbird-mls-account-deletion-authority-v2\0`, the u32-BE length-prefixed key ID, and the complete `catbird-mls-account-deletion-v1\0` record transcript. A verified entry records `native.account_deleted:{cid}:{did}`, drops that account's queued witness copies and evidence, and purges its local messages. Restore also applies the entries listed in `getConversationState.accountDeletions`. Restore and `open_rescued_owner_batch` hide every copy of the account's messages that its receipt orders before the deletion.

**Close.** `apply_terminal_close` erases the MLS group, caches and epoch secrets. It also erases the conversation's pending-op journals, archive queue, retained evidence and staged C33 opening. Local message rows stay. Nothing is archived or rescued for that conversation afterwards. Closing requires an authorized, cid-bound signed wrapper.

**NSE.** `process_push_notification` opens the same `<storage_root>/catbird-mls/<sha256(did)>.db` with `OpenMode::PushExtension`.
- A fetched batch must be contiguous from `last_seq + 1`; every application entry's I13 receipt must bind that outer seq, generation, sender, message and archive commitment before any durable write.
- With no network transport, or after a bounded fetch failure, an in-order inline application up to 2,200 bytes may still produce a preview after MLS decryption, the current cached PDS-authorized sender leaf-key (`I4`), AAD message ID/archive commitment, and original-sender attestation all authenticate its content. `receipt_verified = false` means exactly that this content has **no sequencer receipt**: it does not prove the sequencer accepted the entry, its sequence, or its order. Until foreground sync consumes the entry, an inline wake still inside the retained sender-ratchet window can therefore be replayed, reordered, or previewed even if it was never sequenced. The app must label this preview as unsequenced. The outer write transaction rolls every such exit back, and Rust and the Swift adapter do not post a did-commit notification for it.
- A gap, receipt mismatch or unverifiable entry returns the generic foreground-sync preview and rolls the transaction back.
- A verified Commit writes `conversation_coords:{cid}` from its authenticated commit-AAD prior. The app's `write_tx` reconciles `PRAGMA data_version` inside `BEGIN IMMEDIATE` and evicts cached groups before mutating (`I7`).

OAuth requests must use `REQUIRED_LABYRINTH_OAUTH_SCOPES` with explicitly stated
`read/create/update/delete` actions and the declared record collections. The old
default-action Space grants require reauthorization: hardened PDS delegation rejects
them even if a normalized scope string later looks equivalent. Scope eligibility is a
static coverage check, not proof of original grant provenance; the native credential
exchange remains authoritative and fails closed without dequeuing archive work.

### Async Runtime Bridging

UniFFI callbacks are synchronous. The orchestrator is async. Bridge: `async_runtime::block_on` (`src/lib.rs`), which uses `tokio::task::block_in_place` inside Tokio or falls back to the crate-internal 4-thread runtime. **Keep callbacks fast — they block a thread.**

### Recovery State Machine

This crate exposes a **7-variant** `ConversationState` enum
(`src/orchestrator/types.rs`, search `pub enum ConversationState`) tracking
**per-conversation, orchestrator-internal** lifecycle:

```
Initializing → Active → ForkDetected → NeedsRejoin → Failed
                  ↕
        ResetPending / Quarantined
```

- `Initializing` — group is being created but not yet committed
- `Active` — healthy; sending and receiving messages
- `ForkDetected` — fork detected during decryption; fork-readd in flight
- `NeedsRejoin` — flagged for deferred External Commit rejoin
- `ResetPending { new_group_id, reset_generation, notified_at_ms }` — server
  issued a quorum-based group reset (spec §8.6); orchestrator must drop local
  MLS state and join the new group id. Must survive restart (persisted via
  the storage backend).
- `Quarantined { reason, since_ms }` — Layer 3 quarantine: failures classified
  as a *peer's* malformed commit, not local state loss. Suppresses ALL
  auto-rejoin/External-Commit paths (sends blocked, reads work) so one buggy
  peer can't drag healthy clients into an epoch storm. Persisted via
  `MLSStorageBackend::mark_quarantined`. Exits via server reset event, a
  healthy peer commit merging, or user-confirmed manual reset.
- `Failed` — terminal local failure

It's stored in `MLSOrchestrator.conversation_states`
(`Mutex<HashMap<ConversationId, ConversationState>>`) and read/written by
`messaging.rs`, `recovery.rs`, and `groups.rs`.

### Layering: Rust 5 states vs spec 7 states

**The `ConversationState` enum here is NOT the same state machine as the
7-state conversation recovery machine in `docs/MLS_CLIENT_PROTOCOL.md §8.1`** (that spec
lives in the Catbird+Petrel workspace root).

The spec's 7-state machine (`HEALTHY`, `EPOCH_BEHIND`, `GROUP_MISSING`,
`NEEDS_REJOIN`, `RECOVERING`, `UNRECOVERABLE_LOCAL`, `RESET_PENDING`) is a
**client-layer, cross-platform contract**. Each platform's own docs describe where it keeps
that view.

Every platform drives `CatbirdMlsClient` (`src/client/`): CatbirdMLSCore, android, catmos,
catmos-cli, BIRDaemon, and browser WASM through `WasmMlsClient` in catbird-mls-web. `MlsContext`
(`src/mls_context.rs`, `src/mls_engine_context.rs`) is now a crate-private engine, not a
UniFFI object. The old Swift files `ConversationRecoveryState.swift` and
`MLSConversationManager+Sync.swift` no longer exist.

The orchestrator's `ConversationState` belongs to `MLSOrchestrator` embedders (`src/engine.rs`,
the `echo-bot` binary). It is a separate internal bookkeeping enum, and the spec's 7 states
map onto it only loosely. Concretely:
  - `Initializing` has no spec equivalent (pre-creation).
  - `Active` ≈ `HEALTHY`.
  - `ForkDetected` is a **Rust-specific** fork-readd path for
    `recover_fork_by_readding`; the spec treats forks as a flavor of
    `NEEDS_REJOIN`.
  - `NeedsRejoin` ≈ `NEEDS_REJOIN`.
  - `Failed` ≈ `UNRECOVERABLE_LOCAL`.
  - `ResetPending` ≈ `RESET_PENDING` (server-issued reset adoption).
  - `Quarantined` is **Rust-specific** (Layer 3 peer-fault quarantine) —
    no spec-7 equivalent.
  - `EPOCH_BEHIND`, `GROUP_MISSING`, and `RECOVERING` have **no direct
    Rust equivalent** — they're observed indirectly via counters in
    `RecoveryTracker` (in-flight rejoin = `RECOVERING`; group-not-found
    propagates from `get_epoch` failures of the crate-private MLS engine).

**Why two machines?** The Rust orchestrator's state tracks the attempt
lifecycle inside its own sync loop: "am I currently allowed to try a
rejoin?" It needs a small vocabulary (5 states) because its only
side-effects are "try to send an External Commit" or "drop the message."
The platform-layer state tracks what to show the user, what persists on
disk, and when to escalate to server-mediated recovery (`S1.1`
pyramid) — concerns that don't exist in the Rust core.

**Do not conflate them in code reviews.** If a PR talks about "the 7
states," it's the client-layer machine. If it talks about `ConversationState`
or `ForkDetected`, it's the orchestrator.

**Drift to watch:** when the spec or client implementation diverges from
what `messaging.rs` writes into `conversation_states`, check whether the
client/server mapping is still semantically correct. The `RecoveryTracker`
counters (`failed_rejoins`, `last_global_rejoin_at`) are the actual
enforcement mechanism for the S1 rate-limits; the `ConversationState`
enum is just diagnostic bookkeeping.

Key `RecoveryTracker` properties:
- **Global 30s minimum** between any External Commit across all conversations
- **Per-conversation backoff**: 30s → 2m → 10m, max 3 attempts
- **GroupInfo 404 circuit breaker**: 3 consecutive 404s suspends attempts
- **Sequencer failover**: 3 failures over 2min triggers `request_failover`
- Trackers are **in-memory only** (reset on restart = natural cooldown)

### Identity Model

- `conversationId` = stable, server-assigned. Use for API calls.
- `groupId` = current MLS group hex ID. Changes on reset. Use for crypto calls.
- After reset: `ConversationView.group_id != ConversationView.conversation_id`. Never confuse them.

### Wire Format

```json
{"version":1,"messageType":"text","text":"..."}
```
camelCase fields (matches iOS Codable). Fallback: raw bytes as UTF-8 (legacy). Embeds carry encrypted blob references, not raw data.

### SQLCipher Configuration

32-byte plaintext header (iOS WAL compat), 256K KDF iterations, 4096 page size, deterministic salt = `SHA-256(key)[..16]` hex. Must match exactly across restarts or database is unreadable.

Every native and web per-account database carries `account_meta.local_state_format_version`. Open creates the row only in a completely empty database; any non-empty database with a missing, older, or newer version is refused before schema or owner metadata writes with `LocalStateFormatUnsupported { found, required }`. There is intentionally no Round 4 migration: the app must wipe local MLS state and re-enrol.

### Traffic-Analysis-Resistant Padding

Outgoing ciphertext padded to buckets `[512, 1024, 2048, 4096, 8192]` bytes using `[4-byte BE length][ciphertext][zeros]`.

## Coding Conventions

- `cargo fmt` + `cargo clippy --all-targets --all-features` must be clean before commit
- All spec constants in `orchestrator/constants.rs` — never hardcode timers/thresholds
- Orchestrator impl blocks split across files (`groups.rs`, `messaging.rs`, `sync.rs`). Keep files under ~200 lines.
- Trait default methods = no-ops for backward compat. New required methods must have defaults until all platforms implement them.
- FFI entry points use `std::panic::catch_unwind`. Never let panics cross the FFI boundary.
- Use `async_runtime::block_on`, not `RUNTIME.block_on()` directly (handles catmos/Tauri case).
- `MLSMessagePayload` JSON fields must match iOS Codable exactly (camelCase via `#[serde(rename_all = "camelCase")]`).

## Gotchas

- **Async bridge blocks threads.** UniFFI callbacks calling async orchestrator code do `block_in_place`. If Swift holds locks during a callback → deadlock.
- **GroupId changes on reset; ConversationId does not.** Always use `group_id` for crypto, `conversation_id` for API.
- **SQLCipher plaintext header = 32 bytes.** Non-standard config for iOS GRDB WAL compat. Changing the key or salt derivation makes old databases unreadable.
- **Own-commit dedup = SHA-256(ciphertext).** TTL 300s. If you change commit construction, verify the hash still matches echoed commits.
- **`groups_being_created` set prevents sync from deleting nascent groups.** Group is added before server call, removed after. Sync must check this set.
- **Voice encoding compiles on all native targets including WASM.** `audiopus_sys` builds statically even for WASM builds. The WASM facade doesn't expose voice, but the code links.
- **Android NDK linkers must be on PATH.** `.cargo/config.toml` specifies per-ABI linkers. `build-android.sh` auto-detects from `~/Library/Android/sdk/ndk`.
- **`uniffi-bindgen` must match the library version.** If you update UniFFI in Cargo.toml, rebuild bindgen before regenerating Swift/Kotlin.
